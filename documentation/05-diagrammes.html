Nomadix — diagrammes d'architecture

Vue complete de la plateforme dockerisee : 10 conteneurs, un point d'entree unique (API Gateway), un registre Eureka, Keycloak comme fournisseur d'identite et RabbitMQ pour les evenements asynchrones. Tous les diagrammes sont du SVG ecrit a la main : aucun acces reseau n'est necessaire pour les afficher (imprimable en PDF tel quel).

1. Architecture de deploiement

Le navigateur ne connait qu'une seule adresse : http://localhost:8090. Nginx sert l'application Angular et relaie /api/** vers la Gateway, qui resout le service cible dans Eureka et relaie le jeton Keycloak.

Client Service Java / Spring Service Python / FastAPI Service Node / Express Infrastructure Identite

Les ports publies sur l'hote ne servent jamais au routage interne : la Gateway et Feign utilisent le nom Compose et le port interne (traveler-service:8081, conference-service:3000...). Un conteneur ne peut joindre ni localhost ni une IP 172.20.x.x d'un autre conteneur.

2. Modele de domaine

Une base par service, aucune cle etrangere entre bases : les identifiants (travelerId, flightId) sont des references logiques verifiees par OpenFeign au moment de l'appel.

Traveler nomadix_traveler_db

  • id : Long <<PK>>
  • firstName : String
  • lastName : String
  • email : String
  • role : String
  • favoriteFlights : Set<Long>

Flight nomadix_flight_db

  • id : Long <<PK>>
  • flightNumber : String
  • departureCity : String
  • arrivalCity : String
  • departureDate : LocalDate
  • availableSeats : int
  • price : BigDecimal

Booking nomadix_booking_db

  • id : Long <<PK>>
  • travelerId : Long <<ref>>
  • flightId : Long <<ref>>
  • status : PENDING | CONFIRMED | CANCELLED
  • totalPrice : BigDecimal
  • createdAt : Instant

Conference memoire

  • id : number
  • title : string
  • location : string
  • date : string (AAAA-MM-JJ)
  • flightId : number | null <<ref>>

Notification memoire + archive

  • id : int
  • traveler_id : int <<ref>>
  • type : flight_delay | booking_confirmed | payment_success
  • message : string
  • status : string
  • sentAt : datetime

ConsumedEvent notifications.json

  • routingKey : string (ex. booking.created)
  • receivedAt : string
  • payload : object (corps AMQP)
RelationCardinaliteMise en oeuvre
Traveler → Booking1 → 0..*bookings.traveler_id, verifie par GET /api/travelers/{id} (Feign) avant l'insert
Flight → Booking1 → 0..*bookings.flight_id, verifie par GET /api/flights/{id} (Feign)
Traveler → Flight (favoris)* → *traveler.favorite_flights (collection d'IDs) enrichie par Feign a la lecture
Conference → Flight0..1 → 1flightId libre, non valide cote serveur Node
Notification → Traveler* → 1traveler_id transmis par l'appelant, aucune validation croisee

Cette absence de jointure distribuee est un choix assume : elle evite le couplage entre bases, au prix d'une coherence applicative (saga + compensation) plutot que transactionnelle.

3. Saga de reservation (chemin nominal)

Une reservation est la seule operation qui traverse trois services en synchrone (OpenFeign) avant de publier un evenement asynchrone (RabbitMQ). C'est le coeur de la demonstration.

Chaque appel Feign porte le jeton de l'utilisateur courant (relaye par BearerTokens) : les services cibles revalident la signature, l'emetteur et l'audience nomadix-api. Timeouts : connexion 2 s, lecture 3 s, circuit breaker 4 s.

4. Flux RabbitMQ (exchange, file, DLQ)

Un seul exchange topic relie les trois producteurs au consommateur Python. La file est durable et possede une dead-letter policy : tout message refuse part dans notification.events.dlq au lieu de boucler.

Console de gestion : http://localhost:15672 (nomadix / nomadix123). Scenarios detailles dans 06-scenarios-test.md et dans le test npm test du service conference pour la partie HTTP.

5. Eureka, Gateway et OpenFeign

Trois mecanismes distincts, souvent confondus : Eureka publie les adresses, Gateway route les appels entrants (HTTP), OpenFeign effectue les appels sortants entre services (HTTP interne).

Service arrete : la Gateway renvoie 500 tant que l'instance est encore enregistree (bail de 90 s), puis 503 une fois evincee. Feign, lui, bascule immediatement sur le fallback (reachable: false en ~3 s).
